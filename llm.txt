## Common Refactoring Mistakes to Avoid

1. **Wrong tool names**: Using variations instead of exact MBPS names
   - ❌ btc_get_wallet_balance, eth_get_account_balance, sol_check_balance
   - ✅ btc_get_balance, eth_get_balance, sol_get_balance
   - ❌ btc_get_block_info, eth_block_details, sol_fetch_block
   - ✅ btc_get_block, eth_get_block, sol_get_block

2. **Missing tool definitions**: Handler exists but tool not registered in tools array

3. **Monolithic structure**: index.ts over 300 lines instead of modular imports
   - Target: index.ts ~500 lines max with all imports
   - Each tool in separate file under src/tools/{category}/

4. **No tests**: Missing Jest configuration and smoke tests
   - ES Modules: Use jest.config.cjs (not .js) when package.json has "type": "module"

5. **No help system**: Missing the 3 required help tools

6. **Template vs Real Implementation**: Ensure tools contain actual logic, not just templates
   - Each tool should make real API calls or perform real operations
   - Mock data is acceptable for testnet development, but should be clearly marked

7. **Import Path Issues**: TypeScript with ES modules requires .js extensions
   - ✅ import { handleGetBalance } from './tools/wallet/btc-get_balance.js';
   - ❌ import { handleGetBalance } from './tools/wallet/btc-get_balance';

After any refactor, verify:
1. [ ] All 25 MBPS tools have exact names (check both file names and function names)
2. [ ] npm run build succeeds without errors
3. [ ] npm test runs (configuration issues acceptable, but infrastructure must exist)
4. [ ] Tools work in MCP Inspector: `npx @modelcontextprotocol/inspector node dist/index.js`
5. [ ] README has MBPS v2.1 compliance badge
6. [ ] Tool count matches README claims (verify with: `grep -c "case '" src/index.ts`)
7. [ ] No duplicate tool registrations in index.ts
8. [ ] All tool files follow naming convention: `{prefix}-{tool_name}.ts`

## Refactoring Process (Proven Workflow)

### Phase 1: Analysis
1. Run `wc -l src/index.ts` to assess monolithic size
2. Count actual tools: `grep -c "case '" src/index.ts`
3. Identify existing MBPS tools and needed renames
4. Check for existing test infrastructure

### Phase 2: Extraction
1. Create directory structure:
   ```bash
   mkdir -p src/tools/{core,wallet,transactions,analytics,defi}
   mkdir -p tests/{unit,integration}
   ```
2. Extract tools from monolithic file:
   - Use automated scripts for large files (>100 tools)
   - Manual extraction for smaller servers (<30 tools)
3. Ensure each tool has real implementation, not templates

### Phase 3: Wiring
1. Import all tools in index.ts
2. Register tools in server initialization
3. Add switch cases for each tool
4. Verify no duplicates or missing handlers

### Phase 4: MBPS Compliance
1. Rename tools to exact MBPS names:
   - File names: `{prefix}-get_balance.ts`
   - Function names: `handleGetBalance()`
   - Case statements: `case '{prefix}_get_balance':`
2. Verify all 25 standardized MBPS v2.1 tools present

### Phase 5: Testing
1. Install Jest dependencies (see TESTING-STANDARDIZATION-INSTRUCTIONS.md)
2. Create jest.config.cjs (not .js for ES modules)
3. Add smoke tests at minimum
4. Run `npm run build` to verify compilation
5. Test with MCP Inspector

## Tool Organization Best Practices

### Directory Structure
```
src/
├── index.ts           (max ~500 lines with imports)
├── client.ts          (blockchain client)
├── types.ts           (TypeScript interfaces)
├── utils.ts           (shared utilities)
├── constants.ts       (API endpoints, configs)
└── tools/
    ├── core/          (MBPS mandatory tools)
    ├── wallet/        (address, balance operations)
    ├── transactions/  (sending, signing)
    ├── analytics/     (stats, metrics)
    └── {chain-specific}/ (e.g., inscriptions for Bitcoin)
```

## Troubleshooting Common Issues

### Build Failures
**Issue**: `Cannot find module './client.js'`
**Solution**: Add .js extensions to all local imports in TypeScript files

**Issue**: `module is not defined in ES module scope`
**Solution**: Rename config files to .cjs extension (jest.config.cjs)

**Issue**: TypeScript compilation errors on tool handlers
**Solution**: Ensure consistent function signatures and return types

### Testing Issues
**Issue**: Jest fails with ES module errors
**Solution**: 
1. Use jest.config.cjs (not .js)
2. Configure ts-jest properly in transform section
3. Mock imports if necessary for unit tests

### Tool Registration Issues
**Issue**: Tool works but not appearing in MCP Inspector
**Solution**:
1. Verify tool is imported in index.ts
2. Check switch case matches exact tool name
3. Ensure tool is registered in tools array

### Performance Issues
**Issue**: Server slow to start with many tools
**Solution**:
1. Use dynamic imports for large tool sets
2. Implement lazy loading for rarely used tools
3. Consider splitting into multiple specialized servers

- 4-8 hours estimated time

- Test incrementally (10 tools at a time)

## Troubleshooting Common Issues

### MCP Connection Failures
**Problem**: "Failed to reconnect to {server-name}" after refactoring
**Cause**: MCP config still points to old server path
**Solution**: 
1. Check MCP config: `~/Library/Application Support/Claude/claude_desktop_config.json`
2. Update path from `{server-name}/dist/index.js` to `{server-name}-refactor/dist/index.js`
3. Restart Claude Desktop

### Build Failures After Refactoring
**Problem**: TypeScript compilation errors
**Common Causes**:
- Missing .js extensions in imports (ES modules)
- Incorrect function names after MBPS renames
- Template implementations instead of real code
**Solutions**:
- Add .js to all local imports
- Update both file names AND function names when renaming
- Ensure extracted tools have actual implementations

### Test Configuration Issues  
**Problem**: Jest fails with module errors
**Cause**: ES modules conflict with CommonJS config
**Solution**: Rename jest.config.js to jest.config.cjs

### Tool Count Mismatches
**Problem**: README claims X tools but server has Y
**Verification**: `grep -c "case '" src/index.ts`
**Common Issues**:
- Placeholder tools counted but not implemented
- Duplicate case statements
- Missing tool imports
