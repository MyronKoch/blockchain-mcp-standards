# Blockchain MCP Standard v3.0 (BMCPS v3.0) - AI/LLM Quick Reference

## What This Is
The **Blockchain MCP Standard v3.0 (BMCPS v3.0)** is the unified architectural and tooling standard for building blockchain MCP (Model Context Protocol) servers. This is a **standards repository**, not an implementation—it provides specifications, validation tools, and factory scripts for creating compliant blockchain MCP servers.

## Key Facts
- **Version**: 3.0 (January 2025)
- **Supersedes**: MBPS v2.1 (tool requirements) + MSAS v1.0 (architecture standard)
- **Documents**: 10 core standards (reduced from 28 historical documents)
- **Mandatory Tools**: 25 tools every compliant server must implement
- **Scope**: Universal standard for ANY blockchain ecosystem
- **Reference Implementations**: 15 officially documented (Bitcoin, Ethereum, Solana, Polygon, Avalanche, Arbitrum, Base, BNB Chain, Cosmos, Osmosis, NEAR, Sui, TRON, XRP, World Chain)
- **Naming Convention**: `{prefix}_{action}_{resource}` (e.g., `eth_get_balance`, `btc_create_wallet`)

## The 25 Mandatory Tools

Every BMCPS v3.0 compliant server must implement these tools with exact names:

### Core Operations (8 tools)
1. `{prefix}_get_chain_info` - Blockchain network information
2. `{prefix}_get_balance` - Native token balance for address
3. `{prefix}_get_transaction` - Transaction details by hash
4. `{prefix}_get_block` - Block information by number/hash
5. `{prefix}_validate_address` - Address format validation
6. `{prefix}_get_transaction_history` - Recent transactions for address
7. `{prefix}_send_transaction` - Send native tokens
8. `{prefix}_get_account_info` - Account metadata and status

### Wallet Management (3 tools)
9. `{prefix}_create_wallet` - Generate new wallet
10. `{prefix}_import_wallet` - Import from private key/mnemonic
11. `{prefix}_generate_address` - Generate new addresses
12. `{prefix}_get_wallet_info` - Comprehensive wallet details

### Network Management (3 tools)
13. `{prefix}_get_network_info` - Network status and configuration
14. `{prefix}_get_gas_price` - Current gas/fee pricing
15. `{prefix}_get_mempool_info` - Mempool statistics

### Fee Management (1 tool)
16. `{prefix}_estimate_fees` - Fee estimation for transactions

### Token Operations (5 tools)
17. `{prefix}_get_token_balance` - Token balance queries
18. `{prefix}_get_token_info` - Token metadata
19. `{prefix}_transfer_token` - Send tokens
20. `{prefix}_approve_token` - Approve token spending
21. `{prefix}_get_token_allowance` - Check spending allowances

### Help System (3 tools)
22. `{prefix}_help` - Interactive help and guidance
23. `{prefix}_search_tools` - Search tools by keyword
24. `{prefix}_list_tools_by_category` - Browse organized tool catalog

Note: `{prefix}` is the blockchain identifier (e.g., eth, btc, sol, xrp, etc.)

## Mandatory Directory Structure

```
{blockchain}-{network}-mcp-server/
├── src/
│   ├── index.ts              # Entry point (<300 lines ideal)
│   ├── tool-definitions.ts   # Tool registry & schemas
│   ├── client.ts             # Blockchain client wrapper
│   └── tools/                # Tool implementations
│       ├── core/             # REQUIRED: blockchain fundamentals
│       ├── wallet/           # REQUIRED: wallet operations
│       ├── network/          # REQUIRED: network management
│       ├── tokens/           # REQUIRED: token operations
│       ├── help/             # REQUIRED: help system
│       ├── account/          # Optional: extended account features
│       ├── nft/              # Optional: NFT operations
│       ├── defi/             # Optional: DeFi protocols
│       └── [other]/          # Optional: blockchain-specific features
├── tests/                    # Jest test suite
├── package.json
├── tsconfig.json
└── README.md
```

### File Naming Convention
`src/tools/{category}/{prefix}-{tool_name_with_underscores}.ts`

Examples:
- `src/tools/core/eth-get_balance.ts`
- `src/tools/tokens/btc-transfer_token.ts`
- `src/tools/nft/sol-mint_nft.ts`

## Factory Automation

The repository includes Node.js scripts for automation:

### bmcps-factory.js
Generates new BMCPS v3.0 compliant servers from scratch.
```bash
node bmcps-factory.js --blockchain eth --network testnet
```
- Creates complete directory structure
- Generates 25 mandatory tool stubs
- Sets up TypeScript, Jest, and package.json

### bmcps-validation.js
Validates server compliance against BMCPS v3.0.
```bash
node bmcps-validation.js /path/to/server
```
- Checks architecture (directory structure)
- Validates tool naming conventions
- Verifies all 25 mandatory tools exist
- Assigns compliance level (Bronze/Silver/Gold)

### bmcps-testing-framework.js
Sets up comprehensive testing infrastructure.
```bash
node bmcps-testing-framework.js /path/to/server
```
- Generates Jest configuration
- Creates test templates
- Sets up security and performance tests

### implementation-templates.js
Generates tool implementation code.
```bash
node implementation-templates.js --blockchain eth --tools all
```
- Creates tool files with proper structure
- Includes Zod validation schemas
- Adds error handling patterns

## For AI Agents Using This Standard

When helping developers build blockchain MCP servers:

1. **Always reference BMCPS v3.0** (not MBPS or MSAS separately)
2. **Use exact tool names** from 02-UNIVERSAL-TOOL-NAMING-REGISTRY.md
3. **Follow modular structure** (one tool per file in category directories)
4. **Include all 25 mandatory tools** with correct `{prefix}_{action}_{resource}` format
5. **Validate inputs** using Zod schemas
6. **Use McpError** for error handling
7. **Keep index.ts clean** (<300 lines with imports)
8. **Add comprehensive tests** using Jest
9. **Generate via factory scripts** when possible for consistency
